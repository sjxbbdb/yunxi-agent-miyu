## 已落地的 transcript 边界

当前 `run_command` barrier 已覆盖并回归：变量/追加赋值、命令替换、反引号、
重定向、`cd` 后动态相对路径、带路径命令名、quoted `sh`/`bash`/`dash`/`ksh`/
`zsh`、`eval`、`source`/`.`、`xargs` opaque stdin/placeholder、`find -exec`/
`-execdir`/`-ok`/`-okdir`、未引号 process substitution，以及 audited
`sudo/env` wrapper options。未知 wrapper option 继续 fail-closed。

这些都是有界词法/data-flow seam，不是完整 shell parser。函数/别名、动态命令名、
任意 wrapper grammar、嵌入 Python/Node/Perl、父目录替换竞态仍是明确的非目标或
后续设计项。

## 必须保留的退出边界

1. staged transfer 先读取 live tombstone 快照，再在独立 SQLite 文件上事务清理；
   现有提交前失败与本地提交后 child abort 只证明 staged 本地 DB 语义，不证明
   live/staged 跨库原子性，也不覆盖后续 install/rollback 文件系统 crash。
2. overlap 合同是标准读线性化：最终 `tombstone_epoch` 检查是读取线性化点；
   不承诺调用方越过最终检查后的消费窗口仍能严格排除 post-commit 删除。
3. legacy/unknown carrier 没有 typed provenance 时必须按现有策略拒绝或标记 unknown，
   不得通过 transcript 文本反推被删除的 memory id。
4. G4–G9（CompanionPolicy、DecisionPort/Laya、知识库/RAG、自动总结、终端接管、
   TUI 原生化和 G9 hardening）不能因为 G3-05 定向测试通过而提前标记完成。

## G3-05-40 transfer backup-import provenance evidence

The new `transfer::tests::marker_failure_backup_import_preserves_linked_and_unlinked_provenance`
regression uses the production `--force` import path with a marker-stamping
failure. It confirms that the pre-install backup remains importable after the
failed install, and that a fresh import restores the target summary/transcript
provenance plus both an evicted carrier with a provenance link and an unlinked
carrier with identical archived text. WSL Ubuntu-24.04 ext4 `cargo fmt
--all -- --check` and `cargo test -p yunxi-engine --lib transfer --locked --
--nocapture --test-threads=1` passed (`48/48`). This is a backup/archive and
filesystem rollback regression only; it does not claim atomicity across live
and staged SQLite files or OS-crash safety during install.

These authoritative ext4 runs confirm the separate contracts: reset writes durable memory

## G3-05-42 unified reset/association/compact/undo fixture

`agent::tests::context::session_reset_association_compact_undo_keeps_deleted_memory_out`
now covers the missing single-scenario seam with production APIs only. It starts
through `Agent::wipe_session_memory`, recalls a newly written fact through
`MemoryStore::association`, stores a typed `MemoryRef` through
`StateStore::replace_visible_with_summary_with_refs`, resets the session again,
checks the summary checkpoint redaction and recall exclusion, then restores the
pre-compact history with `StateStore::undo_last_turn` and confirms the typed
carrier edge stays removed. No database rows are inserted or updated directly.

Authoritative WSL Ubuntu-24.04 ext4 disposable checkout evidence:

```text
cargo fmt --all -- --check
cargo test -p yunxi-engine --lib agent::tests::context::session_reset_association_compact_undo_keeps_deleted_memory_out --locked -- --exact --nocapture --test-threads=1  # 1 passed
```

This is an evidence fixture for reset→association→compact→undo→redo. The redo
assertion reuses the existing state revision APIs without an LLM or direct SQL;
it proves the tombstoned fact and deleted summary carrier are not resurrected.
It does not cover transfer/backup-import, cross-SQLite atomicity, OS-crash
safety, or free-text scrubbing of ordinary historical tool reports.

## G3-05-43 transcript unknown-wrapper deny boundary

The existing `find_exec_file_access_dataflow_is_denied` regression now includes
`sudo --unknown find . -exec cat {} \;`. The unknown-wrapper form is rejected
conservatively when the nested `find -exec` opaque file consumer is detected;
the case does not claim that the generic wrapper-option walker parsed the
unknown option. This is deliberately a test-only boundary clarification, not
a production parser expansion.

The authoritative WSL Ubuntu-24.04 ext4 combined run passed
`tools::transcript_guard` 29/29 after the added literal. The evidence remains a
bounded lexical/data-flow barrier, not a complete shell or wrapper CLI parser:
functions, aliases, dynamic command names, embedded scripts and
parent-directory TOCTOU are still outside the contract.

## G3-05-44 reset provenance direct regression

`state::tests::compact::reset_cleans_transcript_carriers_without_deleting_files`
now seeds a typed `memory_provenance` row together with a
`transcript_carriers` row through the production compaction API. It asserts both
lookups are populated before `StateStore::reset_conversation`, then asserts the
summary references and transcript lookup are empty afterwards. The test does not
delete or rewrite the transcript file, so it records the intended state-side
cleanup boundary rather than a filesystem scrub guarantee.

The authoritative WSL Ubuntu-24.04 ext4 run passed
`state::tests::compact` 25/25. This closes the previously missing direct evidence
for a non-empty `memory_provenance` reset, but it does not cover
`reset_persona_contexts`, transfer/backup-import in the same fixture,
cross-SQLite atomicity, or OS-crash safety.

## G3-05-45 persona reset provenance scope regression

`state::tests::sessions::persona_reset_clears_memory_and_transcript_provenance_for_targets_only`
seeds a target `yunxi` session and an untouched `other` session with typed summary
references and transcript carriers through the production compaction API. It then
executes `StateStore::reset_persona_contexts("yunxi", "onebot")` and verifies both
provenance lookups are empty for the target while both remain present for the
untouched session. The test exercises scope selection and state-side cleanup without
touching transcript files or introducing direct SQL.

The authoritative WSL Ubuntu-24.04 ext4 run passed
`state::tests::sessions` 17/17. This closes the direct reset-persona evidence gap;
it does not cover transfer/backup-import in the same fixture, cross-SQLite
atomicity, or OS-crash safety.
