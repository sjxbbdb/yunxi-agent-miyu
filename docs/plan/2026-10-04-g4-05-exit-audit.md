# G4-05 退出审计：默认知识库更新事务与收敛

本审计覆盖 G4-05 的四个切片：失败恢复、重索引耗尽可见性、跨进程更新锁、
以及同一 revision 的重复更新收敛。它不把两个独立 SQLite 文件伪装成 OS-crash
跨库事务；该边界继续由 G4-05 的恢复与 freshness gate 负责。

## 已实现并推送

- `f905f538`：optimized checkout/validate 失败回退旧 HEAD；source cache staging
  交换；default namespace 导入失败按 namespace 恢复并清理 orphan，不覆盖 user
  semantic DB。
- `e4187b98`：第 8 次 reindex pass 结束仍有 rerun marker 时写入
  `phase=exhausted`，保留 marker；dashboard 暴露 `passes/max_passes/rerun_pending`，
  旧 `done+marker` 归一为 `queued`。
- `69698f8d`：update、启动初始化、检查和通知共用 `default-kb/update.lock`。
  Linux 使用 `flock(LOCK_EX|LOCK_NB)`，RAII lease 由内核在异常退出后释放；第二
  持有者快速返回稳定 busy 错误，state 写入在临界区重新读取。
- `2dc988bc`：同一 `(source_revision, release_hash)` 且默认文件内容/来源 revision
  均匹配时走 no-op，不再先删快照再重复导入；内容或 revision 不匹配仍完整替换。

## 明确边界

- `meta.db` 与 `semantic_index.db` 仍不是跨文件 OS-crash 原子事务；失败路径使用
  namespace 备份、orphan 清理和 reindex/freshness gate 收敛，恢复后不触碰 user
  namespace 或 memory。
- `update.lock` 只保护默认知识库更新和相关 state 写入，不锁 user KB 查询/写入，
  不复用 `embedding.lock`，不创建第二 scheduler/daemon/reindex runtime。
- G4-05 退出不代表 G4–G9 或长期 goal 完成；goal 继续保持 active，下一阶段进入
  G5-00 的 Laya/DecisionPort 只读来源审计。
