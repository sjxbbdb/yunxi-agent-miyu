# G4-04：知识库更新/导入失败可观测性与收敛

本切片把默认知识库的失败处理从“只返回一个错误”推进为可重试、可解释的最小恢复合同。旧的已导入 revision 仍是运行时事实；新快照在完整预检通过前不会删除旧 default-kb 内容。

## 变更

- `DefaultKbState` 增加向后兼容的 `last_failure_stage`、`last_failure` 和 `last_recovery` 字段。更新/初始化导入失败时记录稳定的机器阶段名和最多 512 个字符的错误摘要；恢复动作明确为“旧快照继续生效，允许重试”。成功提交后清空失败字段。
- `UpdateStage::as_str()` 提供稳定阶段标签，CLI/Web 既有进度回调保持不变；更新流程统一通过阶段标记进入失败记录。
- default-kb replacement 在删除当前快照前完整读取并校验所有候选文件，非法扩展名、空文件、非 UTF-8、超大文件或空快照都会在删除前失败；单文件导入错误不再被静默吞掉。
- `state.json` 改为临时文件写入后替换，并保留 `state.json.bak`。主状态损坏或缺失时可回读备份，避免更新已完成而状态文件半写导致下次启动失效。
- Web 知识库概览的索引状态同时比较内容 hash、namespace、source revision 和 embedding model。相同内容但旧 revision、旧 namespace 或旧模型的向量会显示为 stale，不能伪装成 fresh。

## 保留的边界

- user namespace、memory 数据目录和 memory semantic index 不在 default-kb replacement 的写/删集合中。
- G4-03 的 semantic search freshness gate、单文件 semantic transaction 和 rerun marker 继续生效；partial/旧 revision 向量不会进入语义检索结果。
- meta SQLite 与 semantic SQLite 仍不是跨文件全局事务；操作系统在两个数据库提交之间崩溃的严格原子性、optimized checkout 失败后的旧 HEAD 回退、完整 snapshot journal 留给后续 G4-05 故障注入切片，不在本次声称解决。

## 代码入口

- `crates/yunxi-engine/src/default_kb.rs`：阶段追踪、失败状态、状态文件备份恢复。
- `crates/yunxi-engine/src/tools/knowledge_base/files.rs`：default-kb 全量预检和非静默导入。
- `crates/yunxi-engine/src/tools/knowledge_base/dashboard.rs`：revision/model-aware 索引状态。
- `crates/yunxi-engine/src/tools/knowledge_base/mod.rs`：非法候选文件不能清空旧快照的回归。
