# G4-02-01：Knowledge Base namespace scope 数据面

本切片在 G4-01 的来源元数据之上加入一个只存在于 KB 模块内部的
`KnowledgeCapability`。它是数据面隔离，不是 host/registry 授权系统；当前不接受
namespace 参数，也不把 provenance 当成凭证。后续 G4-02-02 才把 capability 由
可信 host 通过 `ToolCallContext` 注入工具调用。

## 默认兼容策略

`KnowledgeBase::new(config, paths)` 的旧签名保留，默认 scope 在当前 member/root
内允许读取 `user` 与 `linux-command`，只允许写入和删除 `user`。因此既有普通导入、
关键词检索、语义检索和 memory/KB 隔离行为不变；`default-kb/` 的导入、删除和
替换必须使用 KB 内部的 bundled capability。缺少库时 `search_readonly` 仍返回空
结果，不会创建数据库。

内部 `with_capability` 只接受模块私有的 `KnowledgeCapability`。它包含：

- 可读 namespace 集合（覆盖 list/find/read/keyword/semantic/stats）；
- 可写 namespace 集合（import/update）；
- 可删除 namespace 集合（remove/remove_prefix）；
- `bundled_replace` 标志（替换 `default-kb/`）。

模型、JSON 工具参数和路径前缀不能构造或扩大该对象。`bundled_admin` 只在测试中
存在，用来证明内置库替换路径；真实 host 注入留给后续切片。

## 数据面边界

`files.rs` 的文件列表、文件名检索、suffix 解析、读取和删除都先按记录的
`provenance.namespace` 过滤。suffix 的候选只从允许集合产生，拒绝路径统一返回
not-found 形状，不泄露受保护 namespace 是否存在。`index.rs` 的 semantic 查询和
reindex stale-model sweep 同样按 capability 的 namespace 集合；user-only 重建
不能删除 `linux-command` 向量。重建写入的 metadata 继续来自 `FileRecord`，不改
embedding 引擎、chunk、阈值或排序。

## 本切片明确不做

- 不修改 `memory.db`、memory schema/index/删除事务或 transfer registry；
- 不修改 registry、ToolCallContext、Web identity/dashboard、MCP 或 host grant；
- 不新增 namespace 查询参数，不让模型选择权限；
- 不引入新的向量引擎；不处理 G4-03 的 source revision 失效、重建、回滚；
- 不承诺 `kb_meta.db` 与 `semantic_index.db` 的跨 SQLite 原子提交；
- 不把 G4-01 provenance 字段解释为鉴权凭证。

## 验收入口

在 WSL Ubuntu-24.04 ext4 disposable checkout 中执行：

```bash
cargo fmt --all -- --check
cargo test -p yunxi-engine tools::knowledge_base --lib --locked -- --nocapture --test-threads=1
cargo metadata --no-deps --format-version 1
git diff --check
PYTHONDONTWRITEBYTECODE=1 python3 testkit/privacy/g0_scan.py --self-test
PYTHONDONTWRITEBYTECODE=1 python3 testkit/privacy/g0_scan.py --repo .
```

测试覆盖 user/linux-command 读隔离、suffix 解析、普通 owner 对 bundled 写/删的拒绝、
bundled replace、semantic metadata 与 user-only stale sweep、旧 provenance 回读和
memory/KB 独立性。测试结束删除 `/tmp/yunxi-*` 临时 checkout、target、数据库和残留进程。

后续 G4-02-02 需要单独设计并验证：registry/host capability 注入、`kb` 与统一
`read/search` handler 的 context 传递、Web identity 到 namespace 的映射，以及
external trust 的拒绝矩阵。本切片不宣称这些调用方已经获得 namespace 授权。
